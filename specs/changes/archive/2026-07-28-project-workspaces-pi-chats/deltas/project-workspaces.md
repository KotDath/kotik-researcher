# Delta: project-workspaces

## Purpose

Проект для приложения — это директория на диске. Capability покрывает
открытие и создание директорий проектов, список недавних проектов для быстрого
переключения и обработку недоступных директорий. Одновременно открыт один
проект; модель не блокирует добавление метаданных проекта в будущем.

## ADDED Requirements

### Requirement: Открытие существующей директории как проекта

Система ДОЛЖНА позволять пользователю открыть существующую директорию как
проект через системный диалог выбора директории. Открытая директория
становится активным проектом.

#### Scenario: Успешное открытие директории

- **WHEN** пользователь выбирает существующую директорию в системном диалоге
- **THEN** директория открывается как активный проект
- **AND** директория появляется на первом месте списка недавних проектов

#### Scenario: Отмена диалога выбора

- **WHEN** пользователь закрывает системный диалог без выбора директории
- **THEN** активный проект не меняется
- **AND** список недавних проектов не меняется

### Requirement: Создание нового проекта

Система ДОЛЖНА позволять создать новый проект: пользователь выбирает
родительскую директорию и вводит имя проекта, система создаёт поддиректорию с
этим именем. Система НЕ ДОЛЖНА выполнять git init, создавать шаблонные файлы
или какую-либо структуру внутри — только директорию.

#### Scenario: Создание директории проекта

- **WHEN** пользователь выбирает родительскую директорию, вводит имя
  `my-research` и подтверждает создание
- **THEN** на диске создаётся пустая директория `<родитель>/my-research`
- **AND** она открывается как активный проект
- **AND** она появляется на первом месте списка недавних проектов

#### Scenario: Директория с таким именем уже существует

- **WHEN** пользователь вводит имя, и поддиректория с таким именем уже
  существует в выбранной родительской директории
- **THEN** система показывает понятное сообщение о конфликте имён
- **AND** новая директория не создаётся, существующая не изменяется

### Requirement: Список недавних проектов

Система ДОЛЖНА хранить список недавних проектов (путь + дата последнего
открытия) в JSON-файле в Electron userData. Список ДОЛЖЕН переживать
перезапуск приложения и быть отсортирован по дате последнего открытия (свежие
первыми). Модель хранения НЕ ДОЛЖНА блокировать добавление метаданных проекта
в будущем (имя, описание, настройки).

#### Scenario: Список переживает перезапуск

- **GIVEN** пользователь ранее открывал проекты A и B
- **WHEN** приложение перезапущено
- **THEN** список недавних содержит A и B в порядке последнего открытия
- **AND** по записи из списка проект можно открыть повторно

#### Scenario: Повторное открытие проекта поднимает его в списке

- **WHEN** пользователь открывает проект, уже присутствующий в списке
  недавних
- **THEN** проект перемещается на первое место списка без дублирования записи

### Requirement: Удаление проекта из списка недавних

Система ДОЛЖНА позволять убрать любой проект из списка недавних (не только
недоступный). Удаление из списка НЕ ДОЛЖНО удалять или изменять директорию
проекта на диске.

#### Scenario: Убрать доступный проект из списка

- **GIVEN** проект присутствует в списке недавних и его директория существует
- **WHEN** пользователь выбирает «убрать из списка»
- **THEN** проект исчезает из списка недавних
- **AND** директория проекта на диске остаётся нетронутой

### Requirement: Недоступная директория проекта

Если директория проекта из списка недавних удалена или перемещена вне
приложения, система ДОЛЖНА помечать такой проект как «недоступен» в списке.
При попытке открыть недоступный проект система ДОЛЖНА показать понятное
сообщение и предложить убрать проект из списка.

#### Scenario: Пометка недоступного проекта

- **GIVEN** директория проекта из списка недавних была удалена вне приложения
- **WHEN** пользователь открывает список недавних проектов
- **THEN** проект отображается с пометкой «недоступен»

#### Scenario: Попытка открыть недоступный проект

- **WHEN** пользователь пытается открыть проект, помеченный «недоступен»
- **THEN** показывается сообщение о недоступности директории
- **AND** доступно действие «убрать из списка»

### Requirement: Один проект за раз

Система ДОЛЖНА держать открытым ровно один проект одновременно. Переключение
на другой проект выполняется через список недавних проектов или открытие/
создание директории; предыдущий проект при этом закрывается. Поведение
незавершённой генерации при переключении определяется capability
`pi-chat-sessions` (требование «Фоновая генерация при навигации»).

#### Scenario: Переключение на другой проект

- **GIVEN** открыт проект A
- **WHEN** пользователь открывает проект B из списка недавних
- **THEN** проект B становится активным, проект A закрывается
- **AND** в UI отображаются чаты проекта B
