# Delta: llm-provider-settings

## Purpose

Приложение само управляет конфигурацией LLM-провайдеров и не зависит от
установленного у пользователя pi CLI или настроенного `~/.pi`. Capability
покрывает экран настроек (API-ключи, base-url, модель по умолчанию),
зашифрованное хранение ключей и изоляцию данных pi в собственном каталоге
приложения.

## ADDED Requirements

### Requirement: Экран настроек провайдеров

Система ДОЛЖНА предоставлять экран настроек, доступный в любой момент работы
приложения (не только при первом запуске). На экране пользователь может ввести
API-ключи провайдеров, base-url провайдеров (включая OpenAI-compatible и
локальные endpoints) и выбрать модель по умолчанию.

#### Scenario: Открытие настроек в любой момент

- **WHEN** пользователь открывает настройки при открытом проекте и активном
  чате
- **THEN** отображается экран настроек с полями API-ключей, base-url и модели
  по умолчанию
- **AND** после закрытия настроек пользователь возвращается к чату

#### Scenario: Настройка OpenAI-compatible endpoint

- **WHEN** пользователь вводит base-url локального сервера (например, Ollama
  или LM Studio) и выбирает модель
- **THEN** конфигурация сохраняется
- **AND** новые сообщения в чате направляются на указанный endpoint

### Requirement: Зашифрованное хранение ключей

Система ДОЛЖНА хранить API-ключи, зашифрованными средством safeStorage
Electron. Ключи НЕ ДОЛЖНЫ сохраняться в открытом виде, если шифрование
доступно в ОС. Если safeStorage недоступен (нет системного keyring), система
ДОЛЖНА явно предупреждать пользователя на экране настроек, что ключи хранятся
без шифрования (файл с правами доступа только для владельца).

#### Scenario: Ключи зашифрованы

- **GIVEN** safeStorage доступен в ОС
- **WHEN** пользователь вводит и сохраняет API-ключ
- **THEN** на диске ключ хранится только в зашифрованном виде
- **AND** после перезапуска приложения ключ доступен без повторного ввода

#### Scenario: safeStorage недоступен

- **GIVEN** в ОС нет доступного keyring (safeStorage не может шифровать)
- **WHEN** пользователь открывает экран настроек
- **THEN** отображается предупреждение, что ключи будут храниться без
  шифрования

### Requirement: Автономность от установленного pi CLI

Система НЕ ДОЛЖНА читать пользовательский каталог `~/.pi` и НЕ ДОЛЖНА зависеть
от установленного pi CLI. Все данные pi (сессии, конфигурация провайдеров)
ДОЛЖНЫ храниться в собственном каталоге данных приложения. Приложение ДОЛЖНО
быть полностью работоспособно на машине, где pi CLI никогда не устанавливался.

#### Scenario: Чистая машина без pi CLI

- **GIVEN** на машине не установлен pi CLI и отсутствует `~/.pi`
- **WHEN** пользователь настраивает ключ в приложении и отправляет сообщение
- **THEN** чат работает, сессии сохраняются в каталоге данных приложения
- **AND** каталог `~/.pi` не создаётся и не читается

#### Scenario: Пользовательский ~/.pi не влияет на приложение

- **GIVEN** на машине существует `~/.pi` с ключами и сессиями от pi CLI
- **WHEN** приложение запущено
- **THEN** приложение использует только собственные настройки и каталог
  данных; ключи и сессии из `~/.pi` не подхватываются

### Requirement: Неограниченный набор провайдеров

Система НЕ ДОЛЖНА искусственно ограничивать набор провайдеров LLM: ДОЛЖНА
использоваться дефолтная multi-provider конфигурация pi (все поддерживаемые им
провайдеры). Первоочерёдной проверкой покрываются OpenAI-compatible endpoints,
включая локальные (Ollama, LM Studio, self-hosted).

#### Scenario: Провайдер из дефолтного набора pi доступен

- **WHEN** пользователь настраивает ключ провайдера, поддерживаемого pi из
  коробки
- **THEN** модели этого провайдера доступны для выбора без правок кода
  приложения

### Requirement: Применение настроек без перезапуска

Изменение API-ключей, base-url и модели по умолчанию ДОЛЖНО применяться к
работающему приложению без его перезапуска: следующие отправленные сообщения
используют новую конфигурацию.

#### Scenario: Новый ключ действует сразу

- **GIVEN** сообщение завершилось ошибкой «невалидный ключ»
- **WHEN** пользователь вводит валидный ключ в настройках и повторяет отправку
- **THEN** сообщение успешно обрабатывается без перезапуска приложения
