- 2026-07-28 · СПАЙК photon-node: УСПЕХ без починок · photon-node@0.3.4 — чистый WASM (photon_rs_bg.wasm + JS-обвязка), нативных .node-prebuilds в пакете нет и не требуется на ни одной ОС; pi загружает photon лениво с fallback null (обработка изображений деградирует, агент работает); единственные .node в дереве — TUI-only (win32-console-mode, darwin-modifiers, clipboard), вне InteractiveMode не активируются; asarUnpack `**/*.node` оставлен дефенсивно · проверено: dev (`pnpm dev`), linux-unpacked и AppImage — везде ответ LLM получен (SPIKE_OK, DeepSeek), сессии пишутся в изолированный `<userData>/pi-agent`, `~/.pi` не трогается (tasks 1.4–1.7)
- 2026-07-28 · ESM-миграция: вариант без `type: module` · main собирается с `output.format: 'es'` → electron-vite сам эмитит `out/main/index.mjs`, package.json `"main"` указывает на него; preload остаётся CJS `index.js` — не нужно жонглировать `.cjs`-расширениями, которые потребовались бы при `type: module` в package.json (design.md, решение 2)
- 2026-07-28 · изоляция данных pi · `PI_CODING_AGENT_DIR=<userData>/pi-agent` выставляется в paths.ts до вызовов SDK + явные `agentDir`/`authPath`/`modelsPath` в create-вызовах · env-переменная перенаправляет ВСЕ пути pi (сессии, auth, models, settings) одной точкой; SDK читает её лениво в `getAgentDir()` (design.md, решение 3)
- 2026-07-28 · сессия на чат вместо одного AgentSessionRuntime на проект · `AgentSessionRuntime.switchSession()`/`newSession()` диспозит текущую сессию, а `session.dispose()` вызывает `agent.abort()` — генерация в прежнем чате убивалась бы при переключении, что ломает требование «Фоновая генерация при навигации»; поэтому `createAgentSession` на чат, загружены активный + генерирующие, retire-until-agent_end при смене проекта (обобщение отложенного dispose из design.md, решение 1) · при возврате в проект с фоновой генерацией retired-сессии усыновляются обратно, иначе два AgentSession писали бы в один jsonl
- 2026-07-28 · дедупликация карточек ошибок · одна карточка на логический сбой прогона (флаг `errorSentForRun`, сброс на каждый новый `prompt()` и на `agent_start`); события SDK не глушатся — дедуплицируется только пользовательское следствие · SDK эмитит финальный `agent_end` (willRetry=false) ДО `auto_retry_end(success:false)`, а `prompt()` может реджектиться после старта — без дедупликации один сбой давал две карточки (review, major 1)
- 2026-07-28 · retry дублирует user-сообщение в jsonl — принятый компромисс · в SDK 0.82.1 нет примитива повторного прогона упавшего хода, retry = повторный `prompt()` тем же текстом; после перезагрузки истории дубликат виден в ленте · альтернатива (удаление упавшего хода из jsonl) — вмешательство в формат хранения pi при зафиксированной версии, риск рассинхрона (review, minor 8)
- 2026-07-28 · eslint ignores += `.opencode` · каталог конфигурации агентов — не код приложения; отклонение от скоупа спеки зафиксировано post-hoc (review, minor 9)
