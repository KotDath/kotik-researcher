# Design: project-workspaces-pi-chats

## Контекст

Приложение — каркас Electron + electron-vite + React 19 (собственного
поведения нет). Фактура по pi SDK: [research/2026-07-28-pi-sdk.md](../../../research/2026-07-28-pi-sdk.md)
(уверенность высокая). Ключевые ограничения из неё:

- `@earendil-works/pi-coding-agent@0.82.1` — **ESM-only** (`type: module`,
  только `import`), engines node >= 22.19. Electron 43 в проекте — Node ≥
  22.20, подходит с запасом.
- Нативная зависимость `@silvia-odwyer/photon-node@0.3.4` (Rust/N-API, не
  optional) — работа в упакованном Electron не подтверждена. Главный риск.
- Сессии pi скоупятся по cwd: `~/.pi/agent/sessions/--<path>--/*.jsonl`;
  каталог переопределяется (`SessionManager.create(cwd, sessionDir)`,
  agentDir). Листинг: `SessionManager.list(cwd)`; переименование:
  `appendSessionInfo(name)`; удаления в SDK нет — только ФС.
- Аутентификация `ModelRuntime.create()`: runtime override
  (`setRuntimeApiKey`, не персистится) → `~/.pi/agent/auth.json` → env →
  custom keys из `models.json`. Пути переопределяются:
  `ModelRuntime.create({ authPath, modelsPath })`.
- `AgentSessionRuntime`: после `newSession()/switchSession()` объект
  `runtime.session` заменяется — подписки на события надо перевешивать.

## Цели и не-цели

- Цели: SDK в main-процессе; один AgentSessionRuntime на проект; автономное
  хранение ключей и данных pi; ESM-сборка main; упаковка, работающая на Linux,
  macOS, Windows; спайк photon-node до начала UI-работ.
- Не-цели: RPC-подпроцесс поверх Electron (отвергнут пользователем); fork
  сессий, дерево/branching в UI; настройка tools per-чат; вкладки проектов;
  шаринг конфигурации с pi CLI пользователя.

## Решения

### 1. Интеграция: SDK в main-процессе, один runtime на проект

pi SDK загружается в main-процессе Electron. На активный проект — один
`AgentSessionRuntime`, сконфигурированный с `cwd` = директория проекта.
Переключение проекта: старый runtime помечается на dispose, но если в нём идёт
генерация — dispose откладывается до события `agent_end` (требование «Фоновая
генерация при навигации»). После `newSession()/switchSession()` подписки на
события сессии переоформляются (известная особенность API из research).

Отвергнуто: RPC-подпроцесс (`pi --mode rpc`) — отвергнут пользователем для
Electron вплоть до готовности сменить фреймворк; возвращается к нему только
как часть отдельного решения о Tauri.

### 2. ESM-миграция сборки main

SDK не загружается через `require`. Main-процесс переводится на ESM через
конфигурацию electron-vite (ESM-выход для main, например `.mjs`/формат `es`;
Electron ≥ 28 поддерживает ESM в main, у нас Electron 43). Preload остаётся
CJS с sandbox-совместимым contextBridge (перевод preload на ESM — только если
потребует конфигурация, sandboxed preload в Electron ESM не поддерживает —
учесть при настройке). Миграция — часть спайка (задача 1), т.к. без неё SDK не
импортируется.

### 3. Проброс ключей: setRuntimeApiKey + своё зашифрованное хранилище

Выбран вариант **A: runtime override**:

- Приложение хранит ключи в собственном файле в Electron userData,
  зашифрованном `safeStorage.encryptString` (ключи никогда не попадают на диск
  в открытом виде, если шифрование доступно).
- При создании/пересоздании `ModelRuntime` и при изменении настроек ключи
  пробрасываются через `setRuntimeApiKey` — они живут только в памяти runtime.
  Отсюда бесплатно следует требование «Применение настроек без перезапуска».
- Каталог данных pi переопределяется в собственное расположение внутри
  userData (agentDir/sessionDir) — сессии, auth-файлы pi (если SDK их создаст)
  и `models.json` приложения изолированы от `~/.pi` (требование «Автономность
  от установленного pi CLI»). `authPath`/`modelsPath` указывают внутрь нашего
  каталога; authPath используется не как источник ключей, а чтобы SDK не
  ходил в `~/.pi/agent/auth.json`.

Отвергнут вариант **B: authPath как основное хранилище** — `auth.json` pi
хранится в открытом виде (0600), шифрование safeStorage пришлось бы отказаться
или шифровать поверх чужого формата, который pi 0.x может изменить.

Fallback: если `safeStorage.isEncryptionAvailable() === false` (Linux без
keyring) — хранить файл с правами 0600 и показывать предупреждение на экране
настроек (зафиксировано в требовании «Зашифрованное хранение ключей»).

Base-url и дефолтная модель: через `models.json` в собственном каталоге
(custom models pi) + `setModel` на сессии; экран настроек пишет в свою
конфигурацию и пересобирает models.json для SDK.

### 4. IPC-контракт main ↔ renderer

Preload (`contextBridge`) экспортирует типизированное `window.api`:

- `projects`: open (диалог), create (диалог + имя), list, removeFromList,
  getCurrent; событие смены активного проекта.
- `chats`: list, create, rename, delete, select, search — по активному
  проекту.
- `messages`: send(text), retry, abort.
- Стриминг: main шлёт события (`webContents.send`) по подписке на сессию:
  text_delta, tool_execution_start/update/end, agent_start/end, ошибки.
  Renderer держит локальный стейт ленты; при возврате в чат с фоновой
  генерацией запрашивает снапшот (`session.messages`) и доклеивает дельты —
  дедупликация по позиции/идентификаторам событий.
- `settings`: get, set (ключи, base-url, модель по умолчанию), флаг доступности
  шифрования.

### 5. Хранение списка недавних проектов

JSON-файл в userData: массив `{ path, lastOpenedAt }` — структура расширяема
под будущие метаданные (имя, описание). Запись атомарная (tmp + rename), чтобы
пережить падение. Проверка доступности директории — при чтении списка
(пометка «недоступен») и при открытии.

### 6. Удаление чатов через ФС

SDK удаления не предоставляет: удаление = `shell.trashItem(<sessionFile>)`
(корзина ОС, восстановимо — выбор пользователя). Если trashItem недоступен/
падает (нет корзины) — fallback `fs.unlink`. Активную сессию перед удалением
нужно выгрузить из runtime (переключиться на другую/новую), затем удалять
файл. Риск рассинхрона формата хранения принят: версия pi зафиксирована.

### 7. Упаковка: electron-builder + спайк photon-node

В проекте нет упаковщика — добавляется `electron-builder` (минимальная
конфигурация, targets для Linux/macOS/Windows). Нативный модуль photon-node:
`asarUnpack` для `**/*.node` (и/или явное копирование), верификация prebuilds
под три ОС. Спайк (задачи 1.x) — блокер: минимальный main с SDK, упакованная
сборка на Linux получает один ответ от LLM; prebuilds под macOS/Windows
верифицируются по артефактам пакета. Порядок при провале: чинить упаковку
(asarUnpack, копирование `.node`, пересборка модуля) → если только «грязно» —
стоп фичи, отдельное решение о переезде на Tauri с RPC-sidecar (там RPC
приемлем). Результат спайка фиксируется в decisions.md и в tasks.md (чекбокс).

### 8. Layout UI

Sidebar (имя проекта, список чатов с поиском, «новый чат», «сменить проект»,
вход в настройки) + область активного чата со стримингом и сворачиваемыми
tool-блоками. Без роутинга-фреймворка — два состояния верхнего уровня: чат /
настройки. Состояние ленты чата — в renderer, источник правды истории —
jsonl-сессия pi (перечитывается при открытии чата).

## Риски

| Риск | Митигация |
|---|---|
| photon-node не работает в упакованном Electron | Спайк-блокер первым шагом; asarUnpack/копирование .node; при «грязном» фиксе — отдельное решение о Tauri |
| pi 0.x — API меняется каждые 1–7 дней | Точная фиксация 0.82.1; обновления осознанным решением с чтением changelog |
| Крах агента = крах main-процесса | Принято (SDK-in-process — выбор пользователя); try/catch вокруг prompt-цикла, карточки ошибок |
| Удаление сессий обходом SDK | Фиксированная версия pi; удаление только после выгрузки сессии из runtime |
| safeStorage недоступен (Linux без keyring) | Fallback 0600 + предупреждение в UI |
| Агент с правами приложения в cwd проекта | Осознанно принято; скоуп строго директория проекта |
| Потеря состояния при падении | Сессии пишет pi на диск инкрементально; recent-projects — атомарная запись |
