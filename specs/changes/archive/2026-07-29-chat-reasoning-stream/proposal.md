# Proposal: chat-reasoning-stream

## Зачем

Reasoning (thinking) модели сейчас невидим: события `thinking_start/delta/end`
отбрасываются в main-процессе (`chat-manager.ts` форвардит только `text_delta`),
а уровень thinking нигде не выставляется — SDK-сессия живёт с дефолтом.
Пользователь не видит, «что думает» модель, и не управляет глубиной размышлений.
Фича делает reasoning первоклассной частью чата: стриминг вживую в
сворачиваемом блоке (как в OpenCode) и per-provider настройка уровня в Settings.

## Что меняется

- Чат: события `thinking_*` из pi SDK пробрасываются из main в renderer и
  отображаются сворачиваемым блоком reasoning в хронологической позиции ленты
  (перед текстом ответа; при interleaved thinking — несколько блоков).
  Во время стриминга блок развёрнут, по завершении автоматически сворачивается;
  хедер — иконка-лампочка, лейбл и длительность (тикает вживую). Оформление
  приглушённое: серый (`--text-dim`), курсивный текст с вертикальной
  линией-отступом слева, визуально вторичен относительно ответа.
- Персистентность: reasoning переживает перезапуск приложения (блоки из истории
  всегда свёрнуты, длительность сохранена). Reasoning, оборванный до
  `thinking_end` (ошибка/отмена), в историю не попадает; при auto-retry новый
  блок заменяет оборванный — дублей в ленте нет.
- Настройки: у каждого провайдера — свой запоминаемый уровень thinking
  (off + уровни, поддерживаемые текущей моделью провайдера). Настройка видна
  всегда, даже если модель не поддерживает thinking (тогда чат работает как
  раньше, молча, без плейсхолдеров). Дефолт нового провайдера — включённый
  уровень. Смена уровня применяется ко всем активным сессиям без перезапуска,
  со следующего запроса (текущий стрим не рвётся).
- Антискоуп: пер-чат и пер-модель (внутри провайдера) переопределения уровня —
  не делаем.

## Capabilities

- Новые: нет.
- Изменённые: `pi-chat-sessions` — стриминг и отображение reasoning-блоков,
  их персистентность, поведение при обрыве и auto-retry, молчаливый режим для
  моделей без thinking.
- Изменённые: `llm-provider-settings` — per-provider настройка уровня thinking
  с живым применением ко всем активным сессиям.

## Влияние

- **IPC-контракт расширяется** (`src/shared/ipc.ts`): новые `ChatEvent`
  (`thinking_start/delta/end`) и `FeedItem` kind `'thinking'`; трогаются
  main (chat-manager), preload и renderer (ChatArea, новый ReasoningBlock).
- **Новая поверхность pi SDK:** `setThinkingLevel()`, `getAvailableThinkingLevels()`,
  `supportsThinking()`, события `thinking_*` внутри `message_update`, тип
  `ThinkingContent` в истории сообщений. Справка по API — в design.md
  (урок LRN-20260728-002: не реверс-инжинирить семантику SDK заново).
- **Дедупликация событийной цепочки** (LRN-20260728-002): три события
  `thinking_*` — один логический блок; auto-retry не порождает дубли.
- **Инвалидация после мутаций в main** (LRN-20260728-003): смена уровня в
  Settings явно применяется ко всем загруженным сессиям.
- **Длительность reasoning SDK не хранит** — нужен собственный механизм
  персистентности длительности (решение в design.md).
- **design.md нужен:** справка по thinking-API pi SDK, дедупликация блоков,
  персистентность длительности, применение настройки к активным сессиям.
- Веб-research не требовался: открытые вопросы внутренние (шлёт ли текущая
  модель thinking_* после setThinkingLevel; маппинг уровней на провайдеров) —
  verification-задачи в tasks.md, не блокеры спеки (молчаливое поведение
  зафиксировано как норма).
