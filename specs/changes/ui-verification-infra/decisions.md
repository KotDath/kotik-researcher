# Decisions: ui-verification-infra

- 2026-07-29 · скоуп первого захода · всё сразу (Vitest + Playwright E2E + visual + agent-driven + ui-reviewer + документация) · закрыть LRN-20260729-001 системно, а не частично; цена откладывания — повторение инцидента
- 2026-07-29 · инструмент E2E · Playwright Test (`_electron` API) + `@playwright/mcp` · единый движок для CI-тестов и агентской верификации; рекомендован Electron-доками; WebDriverIO отвергнут: нет MCP-интеграции, сложнее старт
- 2026-07-29 · режимы агент-driven верификации · два режима (быстрый: dev-server + MCP; полный: live Electron через CDP + MCP) с явным разделением в AGENTS.md · быстрый — секунды для итераций implementer'а; полный — реальная main-renderer интеграция для финальной верификации
- 2026-07-29 · отвергнуто: унификация в один режим агента · быстрый не ловит баги IPC/main; полный слишком медленный для итераций
- 2026-07-29 · ui-reviewer · отдельный субагент (`.opencode/agents/ui-reviewer.md`), deny:edit, PASS/FAIL · reviewer проверяет код против спеки, ui-reviewer — UI против `docs/ui-review.md`; разные компетенции, разный инструментарий
- 2026-07-29 · отвергнуто: расширение reviewer'а дополнительным UI-чеком · reviewer уже проверяет код, self-review bias удваивается; deny:edit ui-reviewer'а — дополнительная защита
- 2026-07-29 · FAIL от ui-reviewer · hard gate, блокирует approve без исключений · максимальная защита от визуальных багов; человек видит и решает
- 2026-07-29 · кто вызывает ui-reviewer · оркестратор — диспетчер: reviewer сообщает «нужна UI-проверка», оркестратор вызывает ui-reviewer · reviewer не меняется, оркестратор координирует
- 2026-07-29 · цикл generator/evaluator · максимум 3 итерации, после 3-го FAIL — эскалация к человеку · предотвращает бесконечную «полировку» агентом субъективных деталей (урок Addy Osmani)
- 2026-07-29 · baseline-скриншоты · 5–10 ключевых экранов, в git, только ручное обновление (`--update-snapshots`) · автообновление запрещено: агент может сломать UI и обновить эталон, получив зелёный тест
- 2026-07-29 · отвергнуто: автообновление baseline в CI или агентом · главный риск visual regression — self-reinforcing ошибка: сломал → обновил → «тесты зелёные»
- 2026-07-29 · количество baseline-скриншотов · 5–10, не полное покрытие · совет Kent C. Dodds: один E2E happy path для критичного сценария, остальное — интеграционными тестами; снижает хрупкость и maintenance-нагрузку
- 2026-07-29 · файловая структура тестов · `tests/` в корне, поддиректории `unit/`, `e2e/`, `visual/` · все тесты в одном месте, вне `src/`; отвергнуто: `src/__tests__/` — тесты не код приложения
- 2026-07-29 · Playwright конфигурация · один `playwright.config.ts` в корне, два проекта внутри (`e2e`, `visual`) · единая точка входа, общий fixture
- 2026-07-29 · отвергнуто: раздельные конфиги для e2e и visual · дублирование fixture и общей конфигурации
- 2026-07-29 · два режима E2E-тестов · `pnpm test:e2e` (build + test, для reviewer'а) и `pnpm test:e2e:quick` (dev + test, для implementer'а) · build-режим гарантирует проверку production-сборки; quick-режим ускоряет итерации
- 2026-07-29 · отвергнуто: только build-режим E2E · каждая итерация implementer'а требовала бы полной сборки
- 2026-07-29 · Vitest workspace · два проекта (node + web tsconfig) · разрешает конфликт tsconfig (node vs DOM) без ручного переключения environment
- 2026-07-29 · стратегия селекторов · `data-testid` атрибуты + `page.getByTestId()` · защита от хрупкости CSS-селекторов и DOM-структуры; отвергнуто: ARIA-селекторы — не дают точечной адресации конкретных компонентов
- 2026-07-29 · моки нативных диалогов · `electronApp.evaluate()` для подмены `dialog.showOpenDialog` и аналогов · Playwright не перехватывает системные диалоги; отвергнуто: отдельный IPC-канал для тестов — добавляет код в production только для тестов
- 2026-07-29 · судьба spike.ts / SPIKE_HEADLESS · удалить · новый стек Playwright E2E + MCP + Vitest покрывает все сценарии системно; не плодим зоопарк инструментов
- 2026-07-29 · MCP-сервер · конфиг в `opencode.json` (`mcp.servers.playwright`) · MCP всегда доступен агентам без ручного запуска; ui-reviewer, implementer, reviewer используют одни и те же инструменты
- 2026-07-29 · контракт implementer'а о renderer · строка `Change touches: renderer` (или `main`, `both`) в ответе оркестратору · implementer анализирует свой дифф, а не оркестратор; строка — простой парсимый контракт
- 2026-07-29 · ужесточение протокола идеатора · обязательное покрытие всех измерений карты в vision.md, оркестратор проверяет полноту · унификация качества vision.md; предотвращает пропуск измерений (Risks, Edge cases) до spec-writer'а
- 2026-07-29 · интеграция в SDD · implementer (быстрая самопроверка: unit + E2E quick + dev-server MCP) → reviewer (полная: вызывает ui-reviewer через оркестратора) → оркестратор (диспетчер, проверяет hard gates) · чёткое разделение ответственности на каждом этапе SDD-цикла
