# Критерии UI-проверки

Единые критерии FAIL для визуальной верификации UI (ui-reviewer, reviewer,
implementer при самопроверке). Каждый вердикт FAIL обязан ссылаться на
конкретный критерий из этого документа и подкрепляться evidence
(скриншот / accessibility-дерево).

## Критерии FAIL

1. **Clipping/overlap** — текст обрезан или перекрывает другой элемент.
2. **Элемент вне видимой области** — важный контрол (кнопка, поле, ссылка)
   находится за пределами видимой области и недостижим скроллом.
3. **Неожиданный горизонтальный скролл** — появляется горизонтальная
   прокрутка там, где её не должно быть.
4. **Недоступное содержимое модалки** — содержимое модального окна нельзя
   достичь (скролл не работает, контент уходит за край, закрытие невозможно).
5. **Отсутствующие состояния** — loading, empty или error-состояние не
   показывается там, где оно предусмотрено (спиннер/скелетон, пустой список,
   карточка ошибки).
6. **Неясный primary action** — основное действие экрана визуально не
   выделено или неочевидно.
7. **Сломанный spacing/alignment** — отступы или выравнивание заметно ломают
   существующую дизайн-систему (сетку, ритм, края).
8. **Скрытый keyboard focus** — фокус при навигации с клавиатуры не виден.
9. **Состояние не по спецификации** — взаимодействие приводит к визуальному
   состоянию, отличному от описанного в спеке change.

## Оформление нарушения

Для каждого нарушения указываются:

- **severity:** critical (функция недоступна/контент нечитаем) | major
  (заметный дефект, обход возможен) | minor (косметика)
- **affected screen** — экран/состояние
- **visible evidence** — скриншот / фрагмент accessibility-дерева
- **expected behavior** — что должно быть по спеке/дизайн-системе
- **suggested correction** — предполагаемое направление исправления

## Запрет автообновления baseline

Baseline-скриншоты visual regression (`tests/visual/__screenshots__/`)
обновляются ТОЛЬКО человеком вручную через
`pnpm exec playwright test --project=visual --update-snapshots`.

Агент НИКОГДА не запускает `--update-snapshots` для «починки» упавшего
теста: расхождение скриншота с baseline — это сигнал, а не поломка теста.
Агент репортит расхождение человеку для ручного решения.
