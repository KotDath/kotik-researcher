# ADR 0001: Стек RIG + Tauri + React, ядро отделено от агента

- **Статус:** принято
- **Дата:** 2026-08-15

## Контекст

Целевая концепция — исследовательская платформа (typed artifacts, provenance,
resume, TUI-first тестирование). Первая итерация проекта (Pi SDK + Electron,
сохранена в ветке `backup`) страдала ключевым дефектом: слой агента и ядро
приложения были смешаны, функционал нельзя было протестировать без UI.

Рассматривались варианты:

1. `Rig + Tauri + React`
2. `Pi SDK + Electron + React`
3. `Tauri + Pi RPC + React`

## Решение

Выбран **Rig + Tauri + React** с обязательным архитектурным условием:
ядро отделено от agent runtime и от UI портами-адаптерами.

Структура (Cargo workspace в `src-tauri/`):

- `crates/kotik-core` — контракты (`ChatMessage`, `ChatEvent`, `ChatError`)
  и порт `ChatAgent`. Не зависит от Rig, Tauri, UI. Тестируется мок-агентом
  без сети и API-ключа.
- `crates/kotik-agent-rig` — адаптер Rig (DeepSeek), реализует `ChatAgent`.
  Всё знание о Rig сосредоточено здесь; замена agent runtime затрагивает
  только этот крейт.
- `crates/kotik-cli` — headless терминальный клиент. TUI-first harness:
  весь функционал продукта обязан быть доступен без UI.
- корневой пакет `kotik-researcher` — Tauri-оболочка, тонкий IPC-адаптер
  (DTO → контракты ядра → `Channel` событий во фронтенд). React не владеет
  исследовательским состоянием.

## Последствия

Положительные:

- Ошибка итерации 1 невоспроизводима структурно: core физически не может
  импортировать Rig — это контролируется компилятором, а не дисциплиной.
- Весь функционал тестируется через терминал (`kotik-cli`) без окна,
  а юнит-тесты core — без API-ключа и сети.
- Tauri/React можно переписать или заменить, не трогая ядро.

Отрицательные / принятые риски:

- **Pi TUI больше не является тестовым контуром.** Его заменяет `kotik-cli`;
  это собственный артефакт, который нужно развивать и поддерживать.
- **rig-core молод, API нестабилен** (между 0.41 и main уже переименованы
  ключевые типы стриминга). Миграции будут болезненными, но локализованы
  в `kotik-agent-rig`.
- **Tauri WebView** различается между ОС (webkit2gtk на Linux), слабее
  автоматизация E2E по сравнению с Chromium Electron. Для будущих
  KaTeX/PDF/document canvas потребуется отдельная проверка.
- Два языка (Rust + TS) удваивают стоимость фич на стыке.

## Осознанно отложено (вводить вместе с первыми research-фичами, не раньше)

- Typed research artifacts (ResearchIntent, Evidence, Claim, Synthesis)
- Event log / SQLite canonical store
- Генерация TS-типов из Rust-контрактов (ts-rs/specta)
- Полноценный интерактивный TUI (ratatui)
- Python sandbox

## Критерии пересмотра решения

Решение подлежит пересмотру, если:

- основной цикл не удаётся стабильно гонять через `kotik-cli`;
- миграции rig-core начинают съедать заметную долю времени разработки;
- ограничения WebView блокируют research-UX (PDF, формулы, canvas).
