## 1. Профили-плейбуки

**Статус: реализовано 2026-07-28** (закрыт как механизм). Роутинг-архитектура
пункта (тонкий роутер AGENTS.md + отдельные файлы-процедуры с триггерами,
«не использовать для» и жёсткими чеклистами стадий) выросла органически в
виде opencode-скиллов `.opencode/skills/kotik-*` — под другим именем.
Осталось в бэклоге: (а) первый реальный плейбук — родится из первого релиза
приложения, заранее писать нечего (плейбук — накопитель постмортемов, а
инцидентов нет); (б) вшивание уроков инлайн в чекбоксы процедур — отложено,
уроки пока пишутся в docs/LESSONS.md через /kotik-reflect.

**Что:** отдельные файлы-процедуры для повторяющихся процессов (релиз,
онбординг). `AGENTS.md` — тонкий роутер с таблицей триггер-слов, профиль —
полный источник истины, читается первым. Структура профиля: триггеры →
«Не использовать для» → жёсткий чеклист стадий (пропуск только с явного
согласия пользователя) → принципы → маппинг роль→агент.

**Ключевая идея:** профиль — накопитель постмортемов. Каждый инцидент
заканчивается уроком, вшитым прямо в текст чекбокса со ссылкой на
версию/issue («класс #43», «ударил 3.12.0 И 3.13.0»). So the same hotfix
is never required twice.

**Когда брать:** появится повторяющаяся процедура уровня «публикация
приложения». Кандидатура на первый плейбук — релиз Electron-приложения.

## 2. YOLO-режим (автономная ночная работа)

**Что:** автономный режим implementer'а с жёсткими рельсами:

1. Только изолированная ветка `yolo/<slug>-<timestamp>` от main; никогда не
   коммитить/мержить/пушить в main
2. Валидация (build + typecheck + lint) перед каждым коммитом; сломал —
   откатить именно эту задачу, залогировать, идти дальше
3. Вопросы пользователю запрещены — все решения автономны, с «почему» и
   привязкой к целям
4. Уважать антискоуп (что НЕ делаем — из vision)
5. Один коммит = одна задача (атомарно, для утреннего ревью)

**Предусловия старта:** vision/backlog на диске, чистое дерево, определяются
команды валидации — иначе не начинать. Стоп-команда → отчёт с
рекомендациями «что ревьюить / мержить / выкинуть».

**Когда брать:** базовый SDD-цикл обживётся, появится бэклог мелких задач.

**Оригинал:**
`/home/kotdath/omp/personal/ai/claude-code-agents/agents/control/coordinator-yolo.md`

## 4. Консилиум

**Что:** параллельный разбор важного решения несколькими агентами-экспертами.
3 раунда: (1) изолированные позиции без перекрёстного влияния, (2)
перекрёстная критика, (3) голосование с обязательной записью dissent.
Два anchor-голоса всегда: стратег (долгие горизонты) и адвокат дьявола
(дыры в рассуждении). Триггер: 2+ валидных пути И значимая
необратимость. Дорого — не по умолчанию.

**Когда брать:** первое архитектурное решение с необратимыми последствиями
(выбор storage, IPC-протокол).

## 5. /kotik-reflect — ретроспективный майнинг сессий

**Статус: реализовано 2026-07-28** (скоуп расширен против исходного замысла:
не только ежемесячный майнинг, но и разбор текущей сессии + дочерних по
требованию). Механика: `.opencode/skills/kotik-reflect/` (скилл + скрипт
`scripts/session-digest.mjs`), агент `reflector`, команда `/kotik-reflect
[--days N]`. Хранилище сессий — SQLite
`~/.local/share/opencode/opencode.db`, дети связаны по `session.parent_id`.
Защита от переполнения: детерминированная предфильтрация и бюджеты в
скрипте, drill-down срезами, reflector сырые транскрипты не видит.
Осталось в бэклоге: плагин-счётчики триггеров рефлексии (см. п.3).

**Что:** ежемесячная команда: скан истории сессий opencode по фразам
коррекций («нет», «не так», «откати», «я просил» — список калибруется под
пользователя) → паттерны повторяющихся промахов → предложения правил в
AGENTS.md / docs/LESSONS.md. Ловит то, что онлайн-рефлексия пропустила.

**Методика (по Alderson/Yu):** сессии хранятся локально; поиск по
фразам-коррекциям; дистилляция в prevention-правила; находки только с
одобрения пользователя. Оригинальный эффект: 500 сессий → правила против
«не читает код перед правкой», «латает симптом вместо root cause»,
док-дрейф констант.

**Когда брать:** накопится 30+ сессий истории.
