# Spec: tui-chat

## Purpose

Полноценный терминальный чат с DeepSeek в `kotik-cli`: история сообщений с
прокруткой, стриминг ответов, многострочный ввод и отображение ошибок без
падения приложения — TUI-first интерфейс продукта без десктоп-окна.

## Requirements

### Requirement: Терминальный чат как единственный интерфейс kotik-cli

`kotik-cli` SHALL запускать интерактивный терминальный интерфейс (TUI),
состоящий как минимум из области истории сообщений и поля ввода. Построчный
REPL-режим (чтение строк из stdin и печать потока в stdout) MUST быть удалён.

#### Scenario: Запуск приложения

- **WHEN** пользователь запускает `kotik-cli` с корректным `DEEPSEEK_API_KEY`
- **THEN** открывается TUI с пустой историей сообщений и активным полем ввода

#### Scenario: Отсутствует API-ключ

- **WHEN** пользователь запускает `kotik-cli` без `DEEPSEEK_API_KEY`
- **THEN** приложение завершается с понятным сообщением об ошибке и ненулевым кодом выхода

### Requirement: Отправка сообщений и стриминг ответа

Пользователь SHALL иметь возможность отправить сообщение агенту и видеть ответ,
появляющийся чанками по мере стриминга, в области истории. Пока идёт стриминг,
ввод нового сообщения MUST быть заблокирован или поставлен в очередь (выбор —
в design), чтобы история оставалась консистентной.

#### Scenario: Отправка и потоковый ответ

- **WHEN** пользователь вводит текст и нажимает Enter
- **THEN** сообщение пользователя появляется в истории, а ответ ассистента
  наращивается чанками в той же области по мере поступления

#### Scenario: История учитывается в контексте

- **WHEN** пользователь отправляет второе и последующие сообщения
- **THEN** агент получает всю предыдущую историю диалога (поведение на уровне
  текущего контракта `ChatAgent` не меняется)

### Requirement: Прокрутка истории

Пользователь SHALL иметь возможность прокручивать историю сообщений вверх и
вниз клавишами (PgUp/PgDown и/или стрелки). При ручной прокрутке вверх
автопрокрутка MUST приостанавливаться; при возврате к концу истории —
возобновляться.

#### Scenario: Ручная прокрутка вверх во время стриминга

- **WHEN** идёт стриминг ответа и пользователь прокручивает историю вверх
- **THEN** видимая позиция не сбрасывается вниз с каждым новым чанком

#### Scenario: Возврат к концу истории

- **WHEN** пользователь прокрутил историю до конца вниз
- **THEN** автопрокрутка за новыми чанками возобновляется

### Requirement: Многострочный ввод

Поле ввода SHALL поддерживать многострочный текст: Enter отправляет сообщение,
а перевод строки вставляется отдельной комбинацией клавиш (например,
Shift+Enter, с документированным fallback для терминалов, не различающих
модификаторы).

#### Scenario: Вставка перевода строки

- **WHEN** пользователь нажимает комбинацию перевода строки в поле ввода
- **THEN** в поле ввода добавляется новая строка, сообщение не отправляется

#### Scenario: Отправка многострочного сообщения

- **WHEN** пользователь нажимает Enter в поле с многострочным текстом
- **THEN** весь текст, включая переводы строк, отправляется как одно сообщение

### Requirement: Отображение ошибок без падения

Ошибки во время диалога (сбой сети, ошибка API) SHALL отображаться в области
истории как системное сообщение. Приложение MUST НЕ завершаться аварийно и
SHALL позволять продолжить диалог после ошибки.

#### Scenario: Сбой стриминга

- **WHEN** стрим ответа завершается ошибкой
- **THEN** в истории появляется системное сообщение об ошибке, поле ввода
  остаётся доступным, пользователь может отправить следующее сообщение

### Requirement: Выход из приложения

Пользователь SHALL иметь возможность корректно выйти из TUI (например, Ctrl+C
или командой `/exit`), при этом терминал MUST быть восстановлен в исходное
состояние (raw mode и alternate screen выключены).

#### Scenario: Корректный выход

- **WHEN** пользователь инициирует выход
- **THEN** TUI закрывается, терминал возвращается в обычный режим, код выхода — 0

### Requirement: Отмена текущего запроса по Esc

Во время стриминга ответа пользователь SHALL иметь возможность отменить
запрос клавишей Esc. При отмене стрим прекращается, уже полученная часть
ответа MUST остаться в области истории, после неё в истории SHALL
появиться системное сообщение об отмене. Отменённая пара «вопрос-ответ»
MUST НЕ попадать в контекст агента (историю диалога для последующих
запросов). После отмены приложение SHALL позволять продолжить диалог.
Нажатие Esc вне стриминга SHALL игнорироваться и MUST НЕ изменять поле
ввода.

#### Scenario: Отмена в середине стриминга

- **WHEN** идёт стриминг ответа, агент успел прислать часть текста, и
  пользователь нажимает Esc
- **THEN** стрим останавливается, полученная часть ответа остаётся в
  области истории, после неё появляется системное сообщение об отмене,
  поле ввода снова позволяет отправить следующее сообщение

#### Scenario: Отмена до первого чанка

- **WHEN** пользователь нажимает Esc после отправки сообщения, но до
  получения первого чанка ответа
- **THEN** в истории остаётся сообщение пользователя и появляется
  системное сообщение об отмене; записи ассистента не создаётся

#### Scenario: Отменённый запрос не попадает в контекст агента

- **WHEN** пользователь отменил запрос и отправляет следующее сообщение
- **THEN** агент получает историю диалога без отменённой пары
  «вопрос-ответ» (как её частичного ответа, так и промпта)

#### Scenario: Esc вне стриминга

- **WHEN** стриминг не идёт и пользователь нажимает Esc при
  редактировании поля ввода
- **THEN** ничего не происходит: набранный текст в поле ввода не
  изменяется, запрос не отменяется, приложение не завершается

#### Scenario: Сохранение набранного ввода при отмене

- **WHEN** пользователь набрал текст в поле ввода во время стриминга и
  нажимает Esc
- **THEN** стрим отменяется, а набранный текст остаётся в поле ввода и
  может быть отредактирован или отправлен

#### Scenario: Скролл при отмене

- **WHEN** пользователь отмотал историю вверх во время стриминга и
  нажимает Esc
- **THEN** вид прилипает к низу истории, системное сообщение об отмене
  видно на экране

#### Scenario: Повторный Esc после завершения стрима

- **WHEN** стрим уже завершился (успешно или отменой) и пользователь
  нажимает Esc ещё раз
- **THEN** дополнительных сообщений в истории не появляется, состояние
  приложения не меняется
