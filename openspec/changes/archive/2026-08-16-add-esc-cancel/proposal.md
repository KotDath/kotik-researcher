# Proposal: add-esc-cancel

## Why

В TUI-чате `kotik-cli` запрос к агенту нельзя прервать: стрим либо
дочитывается до конца, либо падает с ошибкой. В исходной спеке TUI
(archive/2026-08-16-add-ratatui-tui, D-Non-Goals) отмена была осознанно
отложена, при этом зафиксировано, что mpsc-архитектура её не исключает.
Пользователь, отправивший неудачный или слишком длинный запрос, вынужден
ждать конца стрима. Пилотная фича для проверки оркестраторного цикла.

## What Changes

- Во время стриминга ответа клавиша Esc отменяет текущий запрос: задача
  стриминга прерывается, частичный ответ остаётся в области истории,
  после него появляется системное сообщение об отмене.
- Отменённая пара «вопрос-ответ» НЕ коммитится в контекст агента
  (поведение как при ошибке стрима).
- Esc вне стриминга игнорируется; набранный в поле ввода текст при
  отмене сохраняется; скролл при отмене прилипает к низу истории.
- Поведение Ctrl+C (выход из приложения) не меняется.
- Приветственная подсказка дополняется упоминанием Esc.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `tui-chat`: новое требование об отмене текущего запроса по Esc
  (частичный ответ, индикация, состояние истории агента, граничные
  случаи клавиши Esc).

## Impact

- Код: `src-tauri/crates/kotik-cli/src/app.rs` (новое действие Cancel,
  редьюсер отмены), `src-tauri/crates/kotik-cli/src/main.rs` (прерывание
  spawn-задачи стриминга). Один крейт, контракты `kotik-core` не
  меняются.
- Десктоп-UI (React + Tauri) не затрагивается — отмена там появится
  отдельным change при необходимости.
- Новых зависимостей нет (механизм отмены — средствами tokio).
