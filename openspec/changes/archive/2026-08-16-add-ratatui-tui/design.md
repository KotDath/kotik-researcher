# Design: add-ratatui-tui

## Context

`kotik-cli` сейчас — 65 строк в `main.rs`: цикл `read_line` → `stream_reply` →
печать чанков в stdout (см. proposal.md — Why). Контракт ядра уже достаточен:
`ChatAgent::stream_reply(history, prompt)` возвращает поток `ChatEvent::Chunk`,
`ChatError` типизирован. Инвариант «ядро ≠ агент ≠ UI» означает, что весь
ratatui-код живёт только в крейте `kotik-cli`; `kotik-core` и
`kotik-agent-rig` не трогаем.

## Goals / Non-Goals

**Goals:**

- TUI на ratatui как единственный интерфейс `kotik-cli` (REPL удаляется).
- Стриминг + ручной скролл истории, многострочный ввод — по спеке `tui-chat`.
- Логика состояния чата (история, скролл, буфер ввода, обработка событий)
  тестируется `cargo test` без реального терминала.

**Non-Goals:**

- Статус-бар, счётчики токенов, индикатор «печатает…» (не выбраны в объём).
- Отмена запроса по Esc (не выбрана; стрим дочитывается или падает с ошибкой).
- Markdown-рендеринг, подсветка кода, мышь, persisted-история между запусками.
- Изменения десктопного UI (React/Tauri) — этот change его не затрагивает.

## Decisions

### D1: Стек — ratatui + crossterm

`ratatui` (актуальная стабильная 0.2x) + `crossterm` как backend и источник
событий клавиатуры. Это стандартная, поддерживаемая связка; termion/termwiz
не рассматриваем (меньше экосистема и хуже кроссплатформенность).
Версии фиксируются в `Cargo.toml` workspace при реализации; `AGENTS.md`
дополняется строкой в таблице зависимостей.

### D2: Структура — чистое состояние + тонкий цикл событий

`kotik-cli/src/` разбивается:

- `app.rs` — структура `App`: история `Vec<ChatMessage>` (плюс служебные
  системные сообщения об ошибках — отдельный вариант отображения, не
  уходящий в контекст агента), буфер ввода, смещение скролла, флаг
  `streaming`. Методы-редьюсеры (`on_key`, `on_chunk`, `on_stream_error`,
  `submit`) — чистые, без IO.
- `ui.rs` — функция отрисовки кадра из `&App` (виджеты `Paragraph` для
  истории и ввода, перенос строк через `Wrap`).
- `main.rs` — инициализация терминала (raw mode + alternate screen через
  RAII-guard, чтобы терминал восстанавливался даже при панике), `tokio`
  цикл: `select!` между `crossterm::event::EventStream` и `mpsc`-каналом
  чанков стрима, отрисовка кадра после каждого события.

Альтернатива «всё в main.rs, как сейчас» отвергнута: нетестируемо, а DoD
требует зелёного `cargo test` с реальным покрытием.

### D3: Стриминг через mpsc-задачу

На каждую отправку порождается `tokio::spawn`: задача гонит
`stream_reply` и шлёт `Result<ChatEvent, ChatError>` в `mpsc::UnboundedSender`.
Цикл событий остаётся единственным владельцем `App` — никаких
`Arc<Mutex>`. Пока идёт стриминг, отправка нового сообщения блокируется
(клавиши продолжают редактировать буфер, Enter игнорируется) — это проще
очереди и сохраняет консистентность истории; спека допускает оба варианта.

### D4: Многострочный ввод

Enter — отправить. Shift+Enter — перевод строки; fallback: Alt+Enter и
Ctrl+J (многие терминалы не передают Shift+Enter — crossterm умеет его
только с kitty keyboard protocol, поэтому fallback документируется в
приветственной строке). Буфер ввода — `String` с позицией курсора;
переносы строк вставляются как `\n`.

### D5: Скролл — ручное смещение + «прилипание» к низу

`App` хранит `scroll: Option<u16>`: `None` = прилипли к низу (автопрокрутка
за чанками), `Some(n)` = ручное смещение от низа. PgUp/PgDown и ↑/↓ меняют
смещение; достижение нуля переводит обратно в `None`. Отрисовка истории —
один `Paragraph` со скроллом; высоты строк считаем через
`ratatui`-layout, точная высота перенесённых строк вычисляется при рендере
(допустимая погрешность скролла при широких переносах фиксируется как
известное ограничение).

### D6: Ошибки — системные сообщения в истории

`ChatError` при стриминге превращается в системную запись в области истории
(визуально отделена, не попадает в `history` для агента). Ошибка старта
(нет `DEEPSEEK_API_KEY`) — как сейчас: сообщение в stderr, exit code 1,
TUI не поднимается.

## Risks / Trade-offs

- [Shift+Enter не различается в большинстве терминалов] → fallback
  Alt+Enter/Ctrl+J, подсказка в UI при запуске.
- [Скролл `Paragraph` с `Wrap` считается в строках после переноса, ручное
  смещение может «прыгать» при изменении ширины] → принимаем погрешность;
  точный виртуальный скролл — отдельная задача, если станет проблемой.
- [Паника внутри TUI оставит терминал в raw mode] → RAII-guard восстановления
  терминала + `std::panic::set_hook` либо guard-структура с `Drop`.
- [API ratatui эволюционирует (0.x)] → версия пинится в workspace, миграции
  локализованы в `kotik-cli`; к тому же риск уже принят на уровне проекта
  для rig-core, подход тот же.
- [Блокировка отправки во время стриминга раздражает при долгих ответах] →
  осознанный trade-off простоты; отмена по Esc — задел следующей итерации,
  канал архитектуры (mpsc-задача) её не исключает.

## Migration Plan

Построчный REPL удаляется в том же change — пользователей у `kotik-cli`,
кроме разработчика, нет, миграция не нужна. Откат = revert коммита.
Скриптовых вызовов `kotik-cli` в неинтерактивном режиме в проекте нет,
ломать нечего (проверено: единственный вызов — `cargo run -p kotik-cli`
из AGENTS.md).
