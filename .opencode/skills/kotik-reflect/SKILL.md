# kotik-reflect — ретроспектива сессий

Вход: скоуп от пользователя. Дефолт — текущая сессия + все дочерние;
`--days N` — майнинг истории за N дней.

## Процедура

1. Запустить экстрактор (bash):
   `node .opencode/skills/kotik-reflect/scripts/session-digest.mjs [--days N]`
   Дайджест детерминированно предфильтрован и бюджетирован (~40KB) —
   сырые транскрипты не читай, их объёмы несовместимы с контекстом.
2. Делегировать дайджест reflector (task). Бриф: сам дайджест + что
   послужило триггером (если пользователь указал на конкретный инцидент —
   сказать какой). Для `--days N` с большим числом сессий: прогнать
   reflector по пачкам (map), затем свести вердикты сам (reduce).
3. Показать пользователю находки **своим сообщением и дословно**: каждое
   предлагаемое правило — отдельным нумерованным пунктом с полным текстом
   правила, адресом (куда вшить) и доказательствами. Ссылка на вывод
   субагента или инструмента («см. выше», «в выводе CLI») не считается
   показом — пользователь не обязан читать простыни tool output. Дать
   рекомендацию, какие правила принять, и запросить одобрение через
   question tool.
4. Запись — только после явного одобрения пользователя: правила в
   AGENTS.md (постоянные, процедурные) или docs/LESSONS.md (уроки с
   контекстом инцидента), правки промптов агентов/скиллов — по месту.
   Без одобрения не писать ничего.
5. Если фраза-коррекция пользователя не поймалась экстрактором или
   ловится лишняя — предложить обновить CORRECTION_PHRASES в шапке
   session-digest.mjs (список калибруется под пользователя).

## Границы

- Не анализировать сам: анализ — reflector, оркестратор ведёт процедуру.
- Не читать БД или транскрипты напрямую — только через session-digest.mjs.
- Находки ≠ автоматические правки: решение о правилах принимает
  пользователь.
